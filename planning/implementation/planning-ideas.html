Make the ocean part of planning

Proposals only — not implemented.

Recommendation: start with a saved-event route and clear overlap warnings. That gives the ocean a useful job while preserving a straightforward schedule. The sketches use illustrative events, not live API data.

1. Saved events become stops on a route

Put a small route in the ocean margin. Saving an event adds a labeled stop. Clicking a stop moves to its day and opens its event card. The boat marks the selected stop. The ocean becomes a second way to navigate a personal plan.

Behavior and constraints
  • Show explicit overlap text and both event names. Never rely on waves or color alone.
  • Keep the list accessible by keyboard. Route stops are ordinary labeled buttons.
  • On mobile, use a compact “My route” drawer instead of squeezing the ocean margin.
  • Chronological order is based on the API; the route is a timeline, not campus geography.
  • No saves yet: offer “Save events to build your route,” without replacing the schedule.

2. Move through time by moving the boat

Place hour marks along a wave's upper edge. Dragging the boat, or choosing an hour, jumps the list to that part of the day. Nearby wave layers shift during the move. This replaces the existing decorative boat strip instead of adding more height above events.

Behavior and constraints
  • Dragging is optional: provide hour buttons and keyboard controls.
  • During the actual event, “Now” returns to current Chicago time. Archived schedules use a selected time, never a fake live state.
  • Honor reduced motion and pause. Jumping to an event still works with no wave movement.
  • Concern: this costs more interaction work than the saved route. Build only if it makes scanning easier in a prototype.

3. “What fits before my next event?”

Offer a chosen time window, or the gap before the next saved event. Show events that fit completely into it, rather than only events that start in it. Example: “I have 45 minutes” → two events ending before the next commitment.

Behavior and constraints
  • Use both start and end times; exclude overlaps with saved commitments.
  • Different venue? Show the location change. Do not invent a walking time from straight-line distance.
  • Use the ocean route's gaps as shortcuts into this filter, with a visible time-window label and Clear action.

4. A compact next-event note

A small paper tag at the ocean edge shows the next saved event, its start time and Open location. It stays reachable while browsing other events. On mobile it becomes a compact bottom bar with enough padding to avoid covering content.

Behavior and constraints
  • Useful during the actual hackathon. For archived days, show the next stop relative to the selected event instead of “starting soon.”
  • One clear event and action. Avoid a second dashboard.
  • This can share the data and layout of idea 1 rather than becoming a separate feature.

Suggested order

Saved route + overlap warnings → next-event note → free-time filter. Try the boat time control as an alternative navigation prototype. Keep the regular schedule available throughout.
