Requested design comparison — September 7, 2026

Assessment: not a 10× improvement. This is a qualitative design judgment, not a measured usability result. Browser-inspected the local app, 2021 schedule, and 2026 schedule. The main official URL now points to a 2027 hype page, so 2026 is the relevant latest schedule comparison. Its initial empty message resolved into live events; it should not be judged as broken from that initial frame.

Our strongest differences are the paper-chart direction, independent ocean motion, search, local saved events and calendar export. But our title/date/route/day/filter/search stack delays the first event. The waves remain large textured background bands rather than a useful part of navigation. Caveat everywhere needs a stronger size, weight and contrast hierarchy. Arrow icons resemble external links but expand details, and mandatory check-in instructions are hidden until expanded.

The 2021 page exposes times, categories and descriptions near the top. The 2026 page has tag and time-range filters, direct building-map links, visible event descriptions and attendee resources. Our search and saves do not replace those advantages. A step-change in usefulness would combine a much shorter schedule header with clear Now/Next, conflict-aware saved plans and direct directions. These are proposals, not implemented behavior or evidence of improved user outcomes.

Recommended order: compress the upper layout; improve typography hierarchy while retaining Caveat; make event actions explicit and expose critical instructions; add direct directions and useful saved-plan conflict information; then refine the ocean's role and artwork scale. No app code was changed for this assessment.

Request and result

Connected the approved design to the public HackIllinois API, added the exact 2021 navigation order, and completed practical schedule behavior. Replaced system handwriting with locally bundled Caveat at the user's request. The older HTML sketch remains intact as design history; use the React app for live events.

  • Days and categories come from events. Events sort chronologically and display Chicago time.
  • Search, category selection and saved-only filtering work together; saves survive reload without an account.
  • Details display locations, safe description links, available venue maps, menus/points and calendar download.
  • Loading, retry, no published events, no matching events and failed storage have explicit states. Failed refresh retains the last loaded events.
  • Mobile navigation, keyboard focus styling, skip link, reduced-motion CSS and ocean pause are included.

API route

The direct browser request failed, and a header check returned HTTP 200 without Access-Control-Allow-Origin. The browser now requests /api/events from its own site. Vite forwards this locally; vercel.json defines the matching deployment rewrite. No secrets, authentication or event mutations are involved. Other hosts must provide the equivalent route; copying dist alone will not work.

import React, { useState } from "react";
import logo from "./logo.svg";
export default function Navigation() {
  const [open, setOpen] = useState(false);
  return (
    <header className="masthead">
      <a href="https://2021.hackillinois.org/" aria-label="HackIllinois home">
        <img className="logo" src={logo} alt="HackIllinois" />
      </a>
      <button
        className="menu-toggle"
        aria-expanded={open}
        aria-controls="site-navigation"
        onClick={() => setOpen(!open)}
      >
        {open ? "Close" : "Menu"}
      </button>
      <nav
        id="site-navigation"
        aria-label="Main navigation"
        className={open ? "navigation open" : "navigation"}
      >
        <a href="https://2021.hackillinois.org/">Home</a>
        <a href="https://2021.hackillinois.org/mentors">Mentors</a>
        <a href="https://2021.hackillinois.org/prizes">Prizes</a>
        <a href="#schedule" aria-current="page" onClick={() => setOpen(false)}>
          Schedule
        </a>
      </nav>
    </header>
  );
}

Limits and skipped checks

  • Vercel deployment routing is configured from official documentation but has not been tested on a deployed site; no deployment was authorized.
  • Reduced-motion styling was inspected, not emulated. No full screen-reader or cross-browser/device audit.
  • Narrow Computer Use viewport requested 390×844; screenshot tool scales its capture. No exact physical-device sizing claim.
  • Calendar content is tested; importing the downloaded file into Apple/Google Calendar was not performed.
  • The 15-second abort timeout is implemented, but an intentionally stalled 15-second browser request was not tested.
  • Native dropdown popup styling follows the OS. Data and linked archive pages may change independently. There is no offline event cache or cross-device save sync.
  • During formatting, Vite restarted and a browser tab showed a connection error. A fresh local tab loaded successfully. This was a development restart, not an API-data failure.
  • No separate linter or type checker was added; plain JavaScript, formatting, tests and build are the available checks.
